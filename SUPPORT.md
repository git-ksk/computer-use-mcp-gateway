# Support

> English is canonical. [日本語版 / Japanese translation](SUPPORT.ja.md)

CUMG is maintained on a best-effort basis and does not provide a commercial support SLA.

Use the repository issue forms for:

- reproducible CUMG bugs;
- documentation defects;
- scoped feature proposals that fit the project boundary;
- usage/setup questions after checking [`docs/GETTING_STARTED.md`](docs/GETTING_STARTED.md) and [`docs/TROUBLESHOOTING.md`](docs/TROUBLESHOOTING.md).

Before filing a bug, reproduce it against a supported CUMG version when practical and separate CUMG behavior from upstream Cua Driver behavior where possible.

**Security vulnerabilities must not be filed as public support or bug issues.** Follow [`SECURITY.md`](SECURITY.md) and use GitHub Private Vulnerability Reporting.

For feature proposals, read [`docs/ROADMAP.md`](docs/ROADMAP.md), [`docs/PROJECT_GOVERNANCE.md`](docs/PROJECT_GOVERNANCE.md), and the V2 product boundary in [`docs/v2/V2_POSITIONING.md`](docs/v2/V2_POSITIONING.md). A technically possible feature is not automatically in scope.
