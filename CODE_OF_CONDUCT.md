# Code of Conduct

> English is canonical. [日本語版 / Japanese translation](CODE_OF_CONDUCT.ja.md)

CUMG welcomes technically rigorous, good-faith participation. This code applies to repository issues, pull requests, reviews, discussions about the project, and other project-managed collaboration spaces.

## Expected behavior

Participants should:

- discuss technical claims with evidence and distinguish facts from assumptions;
- criticize code, designs, and decisions rather than people;
- keep security-sensitive details out of public threads when coordinated disclosure is appropriate;
- respect privacy and avoid posting credentials, private endpoints, personal data, or unrelated desktop contents;
- stay within the project scope and accept a documented `NO-GO` decision without turning disagreement into harassment;
- disclose relevant conflicts of interest when they materially affect a technical or project decision;
- help keep contributor-facing documentation and issue context accurate.

## Unacceptable behavior

The following are not acceptable:

- harassment, threats, discriminatory attacks, or targeted personal insults;
- doxxing or publishing another person's private information without permission;
- sexualized harassment or unwanted sexual attention;
- deliberately exposing credentials, private vulnerability details, or sensitive user/desktop data;
- sustained disruption, spam, impersonation, or knowingly misleading technical claims after correction;
- retaliation against good-faith bug, security, review, or moderation reports.

## Reporting and enforcement

For ordinary repository moderation concerns that can safely be discussed publicly, report the relevant issue, comment, or pull-request content using GitHub's built-in reporting/moderation tools and provide only the context needed to evaluate the concern.

For sensitive conduct concerns, do not publish personal or confidential details in a new public issue. Use GitHub's platform reporting/abuse mechanisms where appropriate. Security vulnerabilities use the separate private process in [`SECURITY.md`](SECURITY.md).

The maintainer may edit or remove content, lock or limit discussions, close issues or pull requests, or block participation when necessary to protect project safety and productive collaboration. Enforcement decisions should be proportionate to behavior, context, recurrence, and impact rather than technical disagreement alone.

## Project decisions

Maintainer authority and technical decision rules are defined in [`docs/PROJECT_GOVERNANCE.md`](docs/PROJECT_GOVERNANCE.md). This Code of Conduct governs participation behavior; it does not turn every disagreement over scope or architecture into a conduct matter.
