# セキュリティ

> **注意:** この文書は [SECURITY.md](SECURITY.md) の日本語訳です。英語版が正典（canonical）です。

Computer-use はクライアントにデスクトップの機密機能へのアクセスを許可します。このゲートウェイをセキュリティ境界として扱い、単なるトランスポートアダプターとして扱わないでください。

## V1 のデフォルト

- 明示的にレビューされた異なるバインドを除き、`127.0.0.1` でのリッスンのみ；
- リモートアクセス前に認証済み TLS ターミネーションを要求；
- バックエンドを直接公開せず、stdio を使用；
- インバウンドの MCP Host 権限とブラウザ Origin 値を検証；
- ゲートウェイの許可リストが空の場合、すべてのツールを拒否；
- 発見されたすべてのバックエンドツールを公開するには、明示的な `CUMG_ALLOW_TOOLS=*` を要求；
- 呼び出しの転送前に拒否ルールを適用；
- 1 つの物理デスクトップに対する操作をシリアライズ；
- バウンド付きの接続/ツールタイムアウトとリコネクトバックオフを使用；
- 上流のキャンセルを実際の下流の MCP リクエスト ID に伝播；
- 失敗した、タイムアウトした、またはキャンセルされたツール呼び出しを自動的にリプレイしない；
- 生のツール引数、結果、スクリーンショット、クリップボードの値、または資格情報のログを回避。

## ポリシーレイヤー

認可は引き続き正確な名前ベースです。`CUMG_DENY_TOOLS` は `CUMG_ALLOW_TOOLS` を上書きします。

V1 では、監査/レビューの目的で、ツールを `observe`、`interact`、`system`、または `dangerous` に分類します。未知または新しく発見された名前は、レビューされるまで `dangerous` に分類されます。セマンティック分類はアクセスを付与しません、正確な名前の許可リストを拡張しません。

Cua の独自のポリシーエンジンは、引数レベルの制約が重要な場合にオプションの第 2 レイヤーとして機能します。 [`../examples/cua-policy.yaml`](../examples/cua-policy.yaml) を出発点として、対象のマシン向けにレビューしてください。

読み取り専用の操作でも、プライベートなデスクトップデータを公開する可能性があります。スクリーンショット、アクセシビリティ情報、ウィンドウ/アプリのメタデータ、および同様の観機能を機密データアクセスとして扱ってください。

## 失敗とキャンセルのセマンティクス

読み取り専用のディスカバリーは、トランスポート障害の後に再接続してリトライできます。Computer-use のアクションは異なります。デスクトップがすでにアクションを部分的に適用している可能性があるためです。

進行中のツール呼び出しでは、ゲートウェイは下流の MCP リクエスト ID を保持します。北向きリクエストがキャンセルされた場合、ゲートウェイは同じリクエスト ID で下流に `notifications/cancelled` を送信し、リプレイなしでエラーを返します。ツールのタイムアウトは同じリプレイなしルールに従い、リカバリのためのリクエストの前に下流のキャンセルを試みます。

決定論的な CI フィクスチャは、下流のキャンセル ID が進行中のバックエンドリクエスト ID と一致することを検証します。

## Host と Origin の検証

MCP 境界は Host と Origin ガードを使用します。デフォルトで受け入れられる権限/オリジンはループバック指向です。リモートデプロイメントの場合は、正確な期待されるパブリック権限/オリジンを設定するか、信頼できるプロキシで明示的に Host をリライトしてください。プロキシ構成を機能させるためだけにこれらのガードを無効にしないでください。

 [`DEPLOYMENT.md`](DEPLOYMENT.md) を参照してください。

## ヘルスメタデータ

`/healthz` はレディネシーを報告し、ゲートウェイが所有するバックエンドの子プロセスの運用メトリクスを含む場合があります：

- PID；
- 累積 CPU 秒数；
- RSS バイト。

これは生のデスクトップコンテンツを含みませんが、リモート到達可能なヘルスルートは、同じ認証済みデプロイメント境界の後ろに配置すべきです。

macOS では、Cua はサポートされているアプリケーション/デーモンのライフサイクルを使用する場合があります。したがって、これらのメトリクスは、集計された Cua プロセスの使用量ではなく、ゲートウェイが所有する直接の子を説明します。

## Cloudflare デプロイメント

推奨トポロジ：

```text
remote MCP client
    |
authenticated TLS / Cloudflare Access
    |
Cloudflare Tunnel
    |
127.0.0.1:<gateway>
    |
Cua stdio
```

ゲートウェイをループバックに保持してください。実際のトンネルの資格情報、Access トークン、プライベートホスト名、`.env` ファイル、生成されたプライベートキー、PKCS#12 バンドル、またはローカルの `secrets/` ディレクトリをコミットしないでください。リポジトリの無視ルールは、多層防御であり、シークレットマネージャーやリポジトリのシークレットスキャンの代わりではありません。

## ローカル物理デスクトップの受け入れ

アクセシビリティと画面収録の権限を持つ Mac は高信頼マシンです。したがって、物理デスクトップの受け入れはオペレーターが制御し、ローカルのみです。通常の GitHub Actions は GitHub ホステッドランナーを使用し、それらのデスクトップ権限を受け取りません。

信頼できるログイン済み Mac のレビュー済みチェックアウトからのみ、必要なすべての物理アクション ACK 変数が明示的に `1` に設定されていることを確認して `scripts/v2_desktop_acceptance.sh` を実行してください。デイリーワークステーションではなく、専用テスト Mac を優先してください。 [`V2_LOCAL_DESKTOP_ACCEPTANCE.md`](v2/acceptance/V2_LOCAL_DESKTOP_ACCEPTANCE.md) と [`V1_ACCEPTANCE.md`](V1_ACCEPTANCE.md) を参照してください。

P1 の最終物理受け入れは、2026-08-13 に信頼できる `main` コミット `bb39390f3587902a7df918fe1ff4a8b28c328d50` に対して、Desktop E2E run `31675515516` で実行されました。ランナーは専用ラベルでエフェメラルに登録され、信頼できる `main` チェックアウトのみを実行し、ジョブ後に自動的に登録解除されました。V2 P1 ステップは、明示的な解決と再利用の前に、Hub/Agent の再起動と世代進行を生き延びるための正確な隔離を必要としました。

## CI サプライチェーン

通常の CI は読み取り専用のリポジトリ権限とロックされた Rust 依存関係の解決を持っています。実際の Cua スモークの前に、CI は固定された Cua インストーラー、プラットフォームリリースペイロード、およびインストールされた実行可能ファイルの ID を検証し、インストールされたバイナリが独立して検証されたリリースペイロードと一致することを確認します。

決定論的な V1 品質フィクスチャはデスクトップに触れません。これは、キャンセル、100 コール soak 動作、短時間アイドルリソース回帰チェック、バックエンドプロセスのテレメトリ、および選択された適用可能な公式 MCP 準拠シナリオをカバーします。

## ログと報告

ゲートウェイの監査ログは、ツール名、セマンティッククラス、ポリシーの決定、結果、および所要時間などの粗いメタデータを記録します。通常のログには生の引数/結果と資格情報を含めないでください。

セキュリティに敏感な報告については、公開イシューに資格情報や無関係なプライベートなデスクトップデータを含めないでください。可能な場合は、GitHub のプライベート脆弱性報告を優先してください。


## V2 信頼モデル

V2 は、北向きの認証済みクライアントプリンシパル、Hub トランスポート ID、付与署名権限、および Agent デバイス ID を分離します。鍵のローテーションには連続性の証明が必要です。バウンド付きのアドミッションと署名済みキャンセル/リコネクトのセマンティクスは、曖昧な操作に対してクローズ失敗します。完全な侵害されたコンポーネントの分析と非クレームは [`V2_THREAT_MODEL.ja.md`](v2/V2_THREAT_MODEL.ja.md) に文書化されています。

V2-M1 は 2026-08-12 に単一のセキュア Agent 受け入れゲートを通過しました。本番候補は、TLS で保護された gRPC を独立して署名されたアプリケーション ID と分離し、プリンシパル -> 安定したデバイス -> 正確な権限付与を保持し、北向きの OAuth ベアラートークンを Agent に転送しません。曖昧なデスクトップキャンセルは引き続き `indeterminate` であり、リプレイを認可するのではなく、デバイスを隔離します。Linux Hub アプリケーションキーは、パッケージ化されたサービスで systemd 暗号化資格情報を使用します。ACME は通常のサーバー証明書の更新を担当し、Hub/Device/Grant の鍵のローテーションは独立し、連続性を証明された状態を維持します。OpenTelemetry/OTLP のデフォルトのテレメトリは、機密性の高い操作ペイロードを除外します。 [`V2_M1_ACCEPTANCE.md`](v2/acceptance/V2_M1_ACCEPTANCE.md) と [`V2_THREAT_MODEL.ja.md`](v2/V2_THREAT_MODEL.ja.md) を参照してください。

M1 後の P0 強化は、権威ある操作台帳でその曖昧境界を明示的にします。認証済み発行者/サブジェクトの所有権と Agent の世代の両方で決済をフェンスします。派遣された不確実性は、リコネクト/再起動にわたる正確な操作のデスクトップ隔離として持続し、曖昧化前のキューイングされた作業は再開されるのではなくキャンセルされます。再利用には明示的で監査可能で永続化ゲート付きの解決が必要です。回復エビデンス文字列はバウンド付きメタデータであり、生のデスクトップコンテンツ、コマンド、結果、またはシークレットを含んではいけません。 [`V2_P0_EXECUTION_SAFETY.md`](v2/V2_P0_EXECUTION_SAFETY.md) を参照してください。

### V2 ペイロードセーフな可観測性

V2 診断出力はセキュリティ境界です。デフォルトのトレーシングイベントと OTel メトリクスは、生の `DeviceCommand`/`DeviceResult` 値、プロセスの stdout/stderr、シェルテキスト/argv/環境変数値、操作ペイロードからのファイルパスまたはコンテンツ、OAuth ベアラートークンまたはイントロスペクションシークレット、正確な権限付与、プロトコル署名、またはプライベートキー素材を含んではいけません。V2 Hub/Agent/バックエンド/永続化境界で使用される Error と Debug のフォーマットは、安定したエラーコードに縮小されます。予期しない署名済みプロトコルメッセージは、オブジェクトを `Debug` でフォーマットするのではなく、メッセージの種類で表現されます。OAuth デバッグ表現は、イントロスペクションクライアントシークレットと認証済みプリンシパルを編集します。

`operation_id`、安定した `device_id` と Agent `generation` は、安全な状態を相関するために必要であるため、構造化ログに表示される場合がありますが、メトリクスラベルとして使用されることはありません。プリンシパルの発行者/サブジェクトは、デフォルトではログに記録されません。OTel メトリクスの属性は、機能、結果、理由、および永続化コンポーネントなどのクローズドドメインに限定されます。リクエストパス、ツール/コマンド名、プリンシパル、および識別子をメトリクス属性として追加してはいけません。

`RUST_LOG` を通じたより高い冗長性は、ペイロードフリーのポリシーを緩和しません。診断ギャップを補うために、コマンド/結果オブジェクトや基底プロバイダーの例外をログに記録しないでください。代わりに、バウンド付きの `error_code` またはイベントフィールドを追加してください。外部コレクタ、リバースプロキシ、およびサービスマネージャーは、アプリケーション境界を無効にするボディ/ヘッダーのキャプチャを同様に避けるべきです。イベント/メトリクスの分類とインシデント相関キーについては [`DEPLOYMENT.md`](DEPLOYMENT.md#overload-and-observability) を参照してください。

### オプションの MCPUsage セキュリティ境界

Usage 会計は実行権限にはなりません。Hub は最初に北向きの認証を完了し、発行者+サブジェクトを導出し、その後、検証された ID、CUMG `operation_id`、およびバウンド付きツール/会計メタデータのみをループバックサイドカーに送信します。認証資格情報、ツール引数/結果、スクリーンショット、シェルテキスト、ファイルコンテンツ、およびイントロスペクション資格情報は、usage ブリッジを渡りません。現在の RFC 7662 アダプターは、Hub の実行前にベアラートークンを追加で削除します。サイドカーは予期しない予約フィールドを拒否します。

usage reserve/`markLiable()` の失敗は、Agent の派遣前にクローズ失敗します。派遣後の決済失敗は、CUMG の隔離を解除せず、`indeterminate` を変換せず、操作をリトライせず、または競合するプリンシパルを認可しません。MemoryUsageStore の再起動はクォータ状態をリセットできますが、耐久性のある CUMG の安全状態はリセットできません。パッケージ化されたサイドカーは、さらにローカルホストのトラフィックに制約されます。 [`V2_USAGE_ACCOUNTING.md`](v2/V2_USAGE_ACCOUNTING.md) を参照してください。

## V2 P1 固定セットマルチデバイスセキュリティレビュー

P1 は、P0 コアの周りに固定された構成のみを追加します。セキュリティレビューは、要求されたクロスデバイス障害クラスをカバーします：

- **クロスデバイス所有権の滲出：** 各デバイスは、個別の `SingleDeviceHub`、権威あるコントローラー、チェックポイントディレクトリ、キュー、ライブセッション、および世代を所有します。未解決の操作や隔離をエントリ間で転送する API はありません。
- **デバイス ID / 世代の混乱：** ルーティングには正確な事前プロビジョニングされた安定したデバイス ID が必要ですが、選択された P0 サービスは、プロビジョニングされたデバイス ID、署名済みセッション材料、操作 ID、機能リビジョン、および世代を引き続き検証します。リコネクトはそのデバイスの世代のみを進行させます。
- **古いルーティング：** 固定マップは構築後不変です。古い A の結果を B にルーティングできるディスカバリー、再割り当て、または別のデバイスへのフェイルオーバー操作はありません。
- **共有/グローバルキューのバイパス：** P1 は共有キューを導入しません。アドミッション/負荷軽減は、既存のデバイスごとの Hub 内に留まるため、A の隔離を B の容量またはキューを通じてバイパスすることはできません。
- **チェックポイント復元の一貫性：** 構築は重複した状態ディレクトリを拒否します。Hub の再起動は、各 P0 チェックポイントを独立して再構築します。1 つのデバイスの復元に失敗しても、別のデバイスの状態を継承する権限として解釈されません。
- **重複/遅延の結果またはキャンセル確認：** 変更されていない P0 の操作/所有者/世代のフェンスは、古い決済と重複した最終化を拒否します。個別のサービスインスタンスはさらに、署名済み A ストリームが B の実行ストリームになることを防止します。
- **解決ターゲットの混乱：** 回復は正確なデバイスの `HubHandle` と正確な曖昧な操作 ID を通じて呼び出されます。別のデバイス上の同じように見える操作を解決できるフリート全体の検索はありません。
- **侵害されたバックエンドのエビデンス：** 変更されていない信頼境界。悪意のある認証済み Agent/バックエンドは、終端エビデンスを虚偽に主張したり、CUMG の外部で副作用を実行したりする可能性があります。参照エグゼキューターは、準拠するバックエンドに対するアダプター分類ルールを証明します。これはリモートアテステーションまたはビザンチン障害耐性の証明ではありません。

証明は意図的に、汎用的な認可、変更可能なデバイス登録/ディスカバリー、フリートスケジューラー、新しいポリシー言語、ネイティブ GUI バックエンド、または ROSClaw フォークを追加しません。

## V2 P2 置換シームのセキュリティ境界

P2 は、実行安全権限を外部認可システム、ポリシーエンジン、デバイスファブリック、または Computer Use ランタイムに委任しません。詳細なレビューは [`V2_P2_REPLACEMENT_SEAMS.md`](v2/V2_P2_REPLACEMENT_SEAMS.md) にあります。

2 つの新しいシームは、意図的に一方通行で狭窄です：

- `DeviceCapabilityAuthorizer` は、1 つの認証済みプリンシパルが 1 つの安定したデバイス ID で 1 つの正確な `DeviceCapability` を使用できるかどうかにのみ応答できます。操作を作成/解決したり、所有権/世代を変更したり、隔離を解除したり、北向きのベアラートークンを Agent に転送したりすることはできません。
- `ComputerUseBackendAdapter` は、型付きの機能をアドバタイズし、バックエンド固有の GUI 観察をバウンド付きの CUMG モデルに正規化し、既存の `BackendExecutionOutcome` を返すことができます。Hub 台帳または解決パスを所有することはできません。バックエンドのツール/セッション名自体は認可機能ではありません。十分なバックエンドエビデンスのない、キャンセル、タイムアウト、切断、またはその他の副作用後の不確実性は、`indeterminate` のまま、変更されていない Hub 隔離パスに流れ込む必要があります。GUI スナップショットは、機密性の高いウィンドウタイトル、ラベル、値、およびスクリーンショットを含む可能性があります。これらはリクエスト結果のまま、デフォルトのテレメトリにコピーしてはいけません。

将来の SINT/Grantex/Open Agent Auth/OPA/Cedar アダプターは、認可状態が利用できないまたは曖昧な場合にクローズ失敗する必要があります。将来の Arm Device Connect またはその他のファブリック統合は、ディスカバリーと生存性をルーティング入力としてのみ扱う必要があります。これらは、所有権の証明、安全な決済、または安全な再利用の証明となることはありません。将来の OpenClaw またはその他の Computer Use アダプターは、2 つ目の権威あるアクションライフサイクルを導入するのではなく、CUMG 操作 ID とフェンスの下のエグゼキューターとして留まる必要があります。

既存の侵害されたバックエンド境界は引き続き適用されます。悪意のある認証済みバックエンドは、主張された結果について嘘をついたり、CUMG の外部で行動したりする可能性があります。アダプターシームはリモートアテステーションを作成しません。P2 は、その信頼境界を大きくしないように設計されています。
