# アーキテクチャ

> **注意:** この文書は [ARCHITECTURE.md](ARCHITECTURE.md) の日本語訳です。英語版が正典（canonical）です。

V2 Hub + V2 Agent が推奨ランタイムです。V1 は回帰・リファレンス用として `v1_gateway` のまま保持されています。

## V1 レガシー・リファレンス

ゲートウェイは MCP サーバーであり、MCP クライアントでもあります。

```text
Northbound                                  Southbound

MCP client
    |
    | MCP Streamable HTTP /mcp
    v
+-----------------------------+
| computer-use-mcp-gateway    |
|                             |
|  Host / Origin guards       |
|       |                     |
|  policy / audit             |
|       |                     |
|  dynamic tool snapshot      |
|       |                     |
|  backend abstraction        |
+-------|---------------------+
        |
        | MCP stdio
        v
   cua-driver mcp
```

### 責務

**ゲートウェイ**
- MCP トランスポート境界
- Host/Origin トランスポートガード
- バックエンドライフサイクル
- 動的ツールディスカバリーとキャッシュ済みポリシーフィルタ済みスナップショット
- リクエスト転送
- 拒否デフォルトの正確な名前ベースポリシー適用
- 監査/検査のためのセマンティックツールリスク分類
- 上流キャンセル転送
- ヘルスおよび監査メタデータ

**バックエンドアダプター**
- 子プロセス接続ライフサイクル
- 接続および操作タイムアウト
- バウンド付き再接続/バックオフ
- 1 つの物理デスクトップに対する操作のシリアライズ
- 実際の進行中リクエスト ID を使用した下流 MCP キャンセル
- 失敗した、またはキャンセルされた状態変更コールの自動リプレイなし
- プラットフォームがサポートする場合のゲートウェイが所有するバックエンド子プロセス PID/CPU/RSS テレメトリ

**Cua バックエンド**
- スクリーンショット
- アクセシビリティ/UI ツリー
- クリック/タイプ/スクロール
- ウィンドウ/アプリケーション制御
- プラットフォーム権限

## バックエンド抽象化

V1 は Cua から始まりますが、パブリックゲートウェイサーフェスに Cua のセマンティクスをハードコードしません。

```text
Backend
  connect()
  health()
  resource_metrics()
  list_tools()
  call_tool(..., cancellation)
  shutdown()
```

最初の実装は `CuaBackend` です。

## 状態モデル

MCP `2026-07-28` はプロトコルレベルの HTTP セッションを削除しました。パブリックリクエストハンドラは、HTTP MCP セッションに保存されたクライアント状態に依存できません。

アプリケーションレベルの状態は MCP トランスポートセッションとは独立しています：

- `Gateway` は正確な名前ベースポリシー、セマンティック分類器、および共有ポリシーフィルタ済みツールスナップショットを所有します。
- `CuaBackend` は現在の MCP クライアントサービス、その直接子 PID、および同期ロックを所有します。
- `tools/list` はバックエンドディスカバリーを更新します。更新に失敗した場合、最後に取得したポリシーフィルタ済みキャッシュスナップショットを提供できます。
- ポリシーで許可された `tools/call` が現在のスナップショットに存在しない場合、1 回の更新をトリガーし、ディスカバリーがまだツールを確認できない場合はクローズ失敗します。
- バックエンド操作は、カーソル/フォーカス/UI スナップショット状態が共有 mutable デスクトップ状態であるため、シリアライズされます。

## ツール分類

V1 では認可とセマンティック分類を分離しています。

正確なツール名は `CUMG_ALLOW_TOOLS` / `CUMG_DENY_TOOLS` を通じて引き続き境界です。独立して、発見された/呼び出されたツールは以下のように分類されます：

- `observe`（観察）
- `interact`（操作）
- `system`（システム）
- `dangerous`（危険）

既知の Cua 互換名は明示的にマッピングされます。未知の/新しいバックエンドツール名は、レビューされるまで `dangerous` に分類されます。分類は監査メタデータおよびディスカバリーカウントに含まれます。正確な名前ベースの許可リストを暗黙的に拡張することはありません。

## 失敗とキャンセルモデル

読み取り専用のツールディスカバリーは、トランスポート障害の後に再接続してリトライできます。状態変更のコンピューターユースコールは、デスクトップがすでにアクションを部分的に適用している可能性があるため、安全にリプレイできません。したがって、失敗したコールはリカバリが試行された後にエラーとして返されます。

北向き MCP リクエストがキャンセルされた場合、ゲートウェイはそのシグナルを `CuaBackend` に転送します。バックエンドは rmcp の cancellable-request API を通じて下流コールを作成し、実際の下流リクエスト ID を保持し、その ID で `notifications/cancelled` を送信します。キャンセルされたコールはエラーとして返され、リプレイされません。

コールごとのタイムアウトは、同じリプレイなしのセーフティルールに従います：バックエンドは進行中のリクエストに対して下流キャンセル通知を送信し、可能な場合、後続のリクエストのために接続を修復します。

## ヘルスおよびリソーステレメトリ

`/healthz` はゲートウェイが直接所有するバックエンド子プロセスの、バックエンドの準備状態およびオプションの `backend_resources` スナップショットを報告します：

```json
{
  "status": "ok",
  "backend": "ready",
  "backend_resources": {
    "pid": 12345,
    "cpu_seconds": 0.12,
    "rss_bytes": 17817600
  }
}
```

`cpu_seconds` は累積プロセス CPU 時間です。`rss_bytes` は常駐メモリです。プラットフォーム/プロセスルックアップがスナップショットを提供できない場合、`backend_resources` は準備状態の決定を変更せずに `null` になり得ます。

macOS では、Cua はサポートされているアプリケーション/デーモンのライフサイクルをプロキシする場合があります。したがって、これらのメトリクスは、集計された Cua プロセスの使用量ではなく、ゲートウェイが所有する直接の子を記述します。

## セキュリティ境界

ゲートウェイはインターネット認証サービスではありません。リモートデプロイメントでは、プロセスをループバックに保持し、認証済み TLS ターミネーションをその前に配置します。`/mcp` 境界はさらに、Host 権威およびブラウザ Origin 値を検証します。

ツール公開は拒否デフォルトです。Cua 独自のポリシーエンジンは、引数認識の機能上限を提供できます。

## V2 ランタイムおよびオプションの会計シーム

実際の北向きランタイムは現在 V2 Hub です。デフォルトバイナリと明示的な `v2_hub` バイナリは、そのエントリポイントを共有します。`v2_agent` は引き続き別個の送信デスクトッププロセスです。古い単一プロセス V1 エントリポイントは `v1_gateway` として保持されています。

使用シームは、権威ある実行コントローラーの外側に意図的に配置されています：

```text
northbound authentication -> verified issuer+subject -> reserve(1)
  -> exact DeviceCapability authorization
  -> CUMG admission / ownership / generation / quarantine
  -> markLiable()
  -> persisted Dispatched -> Agent send
```

`UsageController` には Noop およびローカルサイドカー実装があります。リースは会計状態のみを運びます。`v2_execution_safety` はそれに依存しません。`markLiable()` の失敗は、新しい安全状態ブランチを追加する代わりに、既存の派遣前 CUMG 遷移を通じてキャンセルします。決済失敗は、実行決定後の最善努力の会計失敗であり、ビジネスオペレーションのリプレイをトリガーすることはありません。

ブリッジは CUMG が所有し、ループバックのみで、ベアラートークンまたはツールペイロードを送信しません。最初の実装は `mcp-usage-control` の `MemoryUsageStore` を使用します。詳細は [`V2_USAGE_ACCOUNTING.md`](v2/V2_USAGE_ACCOUNTING.md) を参照してください。

## V2 受け入れ境界

V2 は「V1 にマルチマシンルーティングを追加したもの」では**ありません**。完了した競合ギャップ PoC および GO/NO-GO レビューにより、受け入れ境界は**状態付きインタラクティブデスクトップの委任制御に対する不確実性認識の実行安全**に絞り込まれました。Hub/Agent トポロジは、その安全境界のための実装手段であり、汎用のフリート/デバイスファブリック製品ではありません：

```text
MCP Client
   |
   | MCP
   v
Hub
   |
   | authenticated, typed, backend-neutral command/grant protocol
   v
outbound Agent
   |
   +-- direct process/shell executor
   +-- bounded filesystem read/list capabilities
   +-- GUI/computer-use adapter
        +-- Cua MCP backend
        +-- future native GUI backend
```

差別化された制御セマンティクスは、以下を中心に意図されています：

- 暗号的デバイスアイデンティティおよび登録；
- 有効期限/失効/リプレイルール付きの短命機能付与；
- 明示的な操作 ID およびデバイスごとのリース所有権；
- クローズ失敗のキャンセル/再接続動作；
- 生のデスクトップコンテンツロギングなしのポリシー決定エビデンス；
- バックエンド非依存の機能契約。

トランスポートは製品境界ではなく、実装選択です。M1 本番候補は、TLS を使用した **gRPC 双方向ストリーミング**であり、以前の生の TLS トランスポートは回帰・リファレンス実装として残っています。アプリケーションコマンド/付与スキーマはトランスポート非依存のままなので、後続の WebSocket、QUIC、またはその他のトランスポートアダプターはセマンティクスを再定義しません。最初の gRPC 移行スライスでは、Protobuf が RPC/キャリアフレーミングを担当し、既存の独立して署名されたアプリケーションメッセージは、境界付きキャリアの内部で変更されません。これは、トランスポート移行とセキュリティプロトコルの同時再設計の結合を意図的に回避しています。

Cua は引き続き重要な GUI/コンピューターユースバックエンドですが、Cua 固有のツール名または通信動作が永続的な Hub-to-Agent プロトコルになってはなりません。レビュー済みのパリティターゲットと状態付きインタラクション境界は、[`V2_CUA_PARITY_MATRIX.ja.md`](v2/V2_CUA_PARITY_MATRIX.ja.md) および [`V2_INTERACTION_CONTEXT.md`](v2/V2_INTERACTION_CONTEXT.md) に文書化されています。したがって、V2 はバックエンド非依存のセマンティック GUI 語彙を定義します：`ListWindows`、`LaunchApplication`、`InspectWindow`、および `VerifyUiState` は型付き CUMG 機能であり、Cua の `list_windows`、`launch_app`、`get_window_state`、`verify_state`、AX ロール、およびセッションヘルパーはアダプターで終端します。これは最小共通分母の制限ではありません：各バックエンドは、実際に実装するセマンティックサブセットをアドバタイズします。詳細は [`V2_GUI_SEMANTIC_CAPABILITIES.ja.md`](v2/V2_GUI_SEMANTIC_CAPABILITIES.ja.md) を参照してください。直接プロセス/シェル実行は Agent 自体が所有し、Cua を通じてターミナルウィンドウを自動化して実装してはなりません。構造化された argv 実行は暗黙的なシェル解析を回避しますが、引き続き `Dangerous` です。スクリプト/インタープリターは任意のコードを実行でき、cwd ポリシーは argv ファイルシステムアクセスを制約しません。したがって、M1 は Agent ネイティブのプロセス付与を正確なデバイス機能にスコープします。別個の `ReadFile`/`ListDirectory` 観察機能は、承認されたルート配下でパスを正規化し、返されたコンテンツにバウンドし、シンボリックリンクエスケープを拒否し、粗いエラーを返します。これらの読み取り専用操作は、より狭い機能サーフェスです。`ExecuteProcess` を制約しません。自由形式のシェル実行は、正確な付与と別個のコマンド/結果型を持つ別個の実装済み `Dangerous` 機能であり、意図的に固定 OS シェルを呼び出し、`ExecuteProcess` を拡張せずにシェル解析リスクを受け入れます。明示的なファイルシステム変更は引き続き別個の将来のより高リスクなサーフェスです。

実装順序は意図的にシェルファーストです：セキュアな Agent コアを確立し、直接プロセス/シェル実行を追加し、それらのワークフローに必要なバウンド付きファイルシステム操作のみを追加し、移行中に GUI/コンピューターユースに Cua を保持し、その後ネイティブ GUI バックエンドを追加します。これにより、GUI バックエンドの交換は、開発および運用タスクに対する Agent の有用性から独立します。

M1 オペレーター向け `v2_agent` プロセスは、本番候補キャリアとして TLS を使用した送信 gRPC 双方向ストリーミングを使用します。Agent ネイティブの作業が非同期受信ループ外で実行されている間も、心拍/キャンセルを受信し続け、トランスポート損失後にバウンド付き再接続を実行します。コンパニオン `v2_hub` プロセスは、単一デバイスの常時稼働 VM ランタイムです：登録された Agent を認証し、リスクのある遷移前に生成/アドミッション状態を永続化し、心拍/オフライン状態を維持し、正確な機能付与を発行し、曖昧な切断結果を保守的に `indeterminate` とマークします。生の TLS キャリアは、デプロイメントデフォルトではなく、回帰・リファレンス実装として残っています。

V2-M0 PoC およびその後の競合レビューは、その停止ルールを適用しました：CUMG は、他の汎用リモートデバイスオーケストレーター、フリートプラットフォーム、デバイスファブリック、リモートデスクトップ、または委任認証プロトコルには拡張されません。

マイルストーンおよび明示的な非目標については [`ROADMAP.md`](ROADMAP.md) を、V2 信頼境界、侵害仮定、鍵ローテーション、リプレイ、キャンセル、および残留リスクについては [`V2_THREAT_MODEL.ja.md`](v2/V2_THREAT_MODEL.ja.md) を参照してください。
