# V2 ステータス

> この日本語版は [`STATUS.md`](STATUS.md) の翻訳です。**英語版を canonical（正典）とし、解釈に差がある場合は英語版を優先します。**

2026-09-02 時点の状況:

- **Desktop semantic path:** complete / accepted。same-context の native element click/type/key targeting と、real-Cua による background AX element-action evidence を含みます。
- **Browser core semantic path:** prepare、bind、inspect、navigate、click、type、dialog、pointer semantics まで complete / accepted です。
- **Browser transfer:** complete / accepted。upload/download は scoped CUMG ref と Agent-private の bounded staging を使用し、任意の host path を northbound に公開しません。private staging を確立できない場合も privacy を保ったまま、Agent startup が失敗した正確な bounded stage / I/O class を host-local に記録します。
- **Optional first-class Human Handoff:** CUMG では bounded Window / Terminal-PTY coordination を accepted 済みです。Window は upstream `WindowHandoffAdapter`、Terminal は upstream `TerminalHandoffAdapter` を使い、PTY/process containment と content-free verification は CUMG に残します。canonical Handoff runtime/checkpoint と Human surface は操作対象 Agent が所有し、Hub は CUMG authorization、ledger、quarantine、conservative pre-dispatch fence を保持します。runtime/transport loss 時は Handoff を迂回せず fail closed します。upstream Window #85 には upstream 自身の first-class same-LAN direct physical rerun が残りますが、CUMG #152 は closed のままです。
- **Current execution-safety boundary:** durable execution-safety schema は **v11** です。effectful work の結果が曖昧なら `Indeterminate` として device を quarantine し、automatic retry / replay は行いません。schema v6 は text/input delivery が適用されたが commit されていない状態を、本当の no-effect resolution と区別します。schema v7 は payload-free / privacy-preserving な text-input evidence envelope と optional keyed candidate matching を追加します。schema v8 は closed recovery-evidence read lane を追加し、明示 allowlist 済みの non-mutating evidence read だけを quarantine 中にも許可します。generic shell/process とすべての mutation/activation/write capability は引き続き拒否されます。schema v9 は caller-retained status-only effectful response-loss recovery、schema v10 は historical `Indeterminate` を変更せず reviewed low-impact ambiguity を継続点として受け入れる local-user-presence `current_state_accepted` retirement disposition を追加します。schema v11 は permanent exact replay tombstone と64件 bounded detailed retirement history を分離し、compact tombstone index は独立して4096件上限・exhaustion 時 fail closed とします。
- **Operator inspection / reconciliation:** `v2_maint inspect-quarantine` は read-only で、raw payload / owner identity を公開せず、以前から device を block している正確な `blocking_operation_id` と bounded recovery metadata を返します。`v2_maint audit-reconciliation` は最新の Hub/Agent durable state を相関し、authoritative terminal evidence、legacy/non-authoritative marker、observational correlation を明示的に区別します。どちらも quarantine を clear せず replay authority にもなりません。`compare-quarantine-request` は correlation-only で、返せるのは `same_request`、`different_request`、`unavailable` だけです。
- **Operator-ready incident brief (#233):** `v2_maint incident-brief` は exact #133 reconciliation audit に bounded quarantine metadata と optional closed-schema diagnostic observation を合成します。external finding は `observational_only` / `unavailable` に強制され、authority を名乗ることも `supported_decisions` を広げることもできません。矛盾は CUMG evidence を上書きせず明示され、shared mutation owner/epoch も available/unavailable/not-requested として read-only に表示できます。JSON / compact text output は raw request/result/desktop/log payload を含みません。
- **Authoritative self-reconciliation / retirement:** execution-safety schema v4 は exact effectful dispatch fence を persist し、fresh authenticated generation 上の exact signed Agent terminal proof が揃う場合だけ self-resolve できます。v5 は permanently unknowable な legacy ambiguity のうち狭い allowlist だけを対象に、exact operation ID を permanent non-replayable のまま維持する別の offline retirement path を追加します。automatic settlement、manual resolution、retirement は意図的に別状態で、いずれも persistence-gated です。
- **Offline recovery compatibility:** authority-bearing `v2_maint resolve` は Hub の完全停止を要求し、authoritative checkpoint の既存 durable writer contract を維持します。maintenance binary は publication 前に representability を検証し、deployed Hub と version-paired artifact として install する必要があります。新しい checkout の maintenance binary を古い deployed Hub 所有 state に対して任意に使う運用は support しません。Issue #100 は complete です。trusted physical macOS の Secure Enclave/user-presence acceptance で実 ambiguous desktop operation を replay せず resolve し、Hub restart 後も durable resolution が authoritative のまま維持されることを確認しました。
- **Privacy-safe northbound failures / actionable indeterminate UX (#115):** live control schema は **v9** です。working-directory denial、timeout、program/environment policy、spawn failure、cancellation、`agent_offline`、`device_indeterminate` など expected execution-policy/runtime failure を bounded client-visible category として維持しつつ、raw path、command、environment value、device identity、provider text、OS error string は公開しません。`device_indeterminate` は execution が既に起きた可能性、blind replay が unsafe であること、exact `get_operation` + reconciliation を優先すること、後続 effectful work には fresh operation ID が必要なことも明示します。command-text heuristic や replay authority は追加しません。unknown internal failure は引き続き generic に fail closed します。
- **Host reliability / diagnostics:** `v2_doctor` は restart-safety state を変更せず、authoritative に証明できる in-band diagnostic self-observation と本当の blocking quarantine を区別します。Browser staging startup failure は bounded local stage/I/O diagnostic を出します。controlled `StorageFull` injection により、Agent checkpoint persistence の容量枯渇が Agent を fail-closed exit させ、remote では `agent_offline` として見えることを確認済みです。失敗前の committed checkpoint / replay barrier は authoritative のまま維持され、容量復旧後は通常の service-manager reconnect で回復します。`v2_doctor` は state/temp filesystem の容量について coarse / read-only signal だけを公開します。
- **Effectful response-loss recovery (#103):** すべての effectful process/shell/Desktop/Browser tool は caller-retained stable `operation_id` を受け取り、Hub-local `get_operation` は Agent liveness や replay に依存せず exact owner と current exact-capability authorization を再確認します。process/shell は bounded output を保持し、それ以外の effectful Desktop/Browser operation は authoritative state/receipt と payload-free `effectful_status` marker だけを persist します。bounded recovery archive は最大8件 / encoded total 256 KiB のままで、unknown/evicted reference が original operation を retry-safe にすることはありません。この marker を含む schema v9 checkpoint の v8 downgrade は拒否します。
- **Local-user online quarantine recovery:** explicit recovery-key provisioning の背後で実装済みです。Agent device key は recovery authority ではなく、fresh Hub-signed challenge は separately pinned P-256 endpoint recovery key だけで解決できます。初期 macOS signer は user-presence access control 付き Secure Enclave key を使用します。automated protocol/persistence coverage と trusted physical acceptance は完了し、local user presence 後にのみ authorization が publish され、ambiguous operation は durably resolve、restart 後も resolution を維持し、旧 operation は replay されませんでした。
- **Lane-scoped operator readiness (#226):** `v2_doctor` は existing authenticated state / capability / quarantine authority から導出する privacy-bounded readiness summary を追加します。control-plane、Computer Use observation、filesystem observation、generic effectful execution、browser-effectful execution を区別し、durable quarantine がある場合は independently healthy な observation lane を隠さず effectful lane だけを `indeterminate_fenced` と表示します。evidence 欠落・不整合は green と推測せず `unavailable` / `unknown` にします。この summary は diagnostic-only で、resolve / retry / replay / dispatch / authority grant はできません。
- **Least-privilege filesystem observation root (#104):** Agent の process/shell cwd root と `ReadFile`/`ListDirectory` root を別設定にします。file root はより狭くでき、canonicalization / symlink-escape denial を維持し、cwd root へのfallbackは行いません。file root 未設定/空設定は startup fail closed とし、packaged service example と upgrade runbook も explicit migration を含みます。
- **Durable single-Mac maintenance status (#234):** reviewed source-build upgrade は owner-private な atomic transaction record に exact CUMG/Handoff source identity、durable phase、bounded terminal class、target runtime generation、rollback identity、mutation-authority owner/epoch、explicit completion gate を記録します。`v2_maint upgrade-status` は read-only で、maintenance resume/retry や quarantine/authority 変更は行いません。source build は default Cargo jobs=2、transaction/service mutation 前に free-space floor 6144 MiB 未満を拒否し、その後の Cargo ENOSPC は install 前の `build_storage_exhausted` として分類します。
- **Durable online-recovery confirmation (#109):** Agent はpending authorizationに対してexactなHub署名 `RecoveryResolved` ACKを検証し、challenge/authorization handoff fileをclearする前にowner-private receiptをatomic保存します。fresh challenge受信時は旧receiptをclearします。`v2_recover resolve --wait-secs` / `v2_recover confirm` はexact request/device/generation/operation/decisionを検証した後だけdurable completionを返し、local authorization publicationだけをterminal successとは扱いません。
- **Unified operator status (#235):** `v2_status` を normal first single-Mac diagnostic とします。JSON schema v1 は既存 #226 readiness、quarantine/recovery、Handoff status、mutation authority、verified runtime identity、#234 maintenance state を bounded な `overall` / `primary_reason` / `next_action` に合成し、別の authority/state machine は作りません。human renderer も同じ schema から生成します。Handoff locator/ID、device/principal identity、payload、credential、grant、fingerprint は出力しません。
- **Guided quarantine recovery (#236 / #255):** `v2_recover guide` は authoritative #233 `supported_decisions` を変更せず、そのsetが空の場合だけ Human-only historical assertion lane を別に表示します。plan schema v2 は Human lane を interactive-only / automatic-selection禁止とし、Agent/LLM/diagnostics は authoritative set を広げられません。Human assertion は既存 `confirmed_completed` / `confirmed_not_executed` を inconclusive audit assessment のまま再利用し、exact challenge/incident再検証、Secure Enclave user presence、#109 durable ACK、no replay、exact quarantine clear、既存 #235 `v2_status` post-check を維持します。`--json` は引き続き read-only planning 専用です。
- **Artifact-backed Product Readiness path (#237):** macOS single-Mac release candidate は CUMG/Handoff runtime source checkout 不要となり、closed manifest で exact CUMG/Handoff commit を bind し、local-user recovery tooling を含み、activation 前 verification、separately provisioned trust/secrets を使う clean first install、既存 one-shot durable upgrade / paired rollback contract を提供します。install success には installed `v2_doctor` / `v2_status` の両方が healthy であることが必要です。Linux/Windows は引き続き reviewed candidate evidence であり official binary-installer claim はしません。
- **Local-Human current-state acceptance (#137):** 完了。`v2_recover accept-current-state` は reviewed `Scroll` / `MovePointer` ambiguity だけに使える独立した authority-bearing macOS path です。separately provisioned Secure Enclave recovery key と fresh signed challenge を再利用し、strictly newer な authenticated/durable generation を要求します。durable audit は `execution_outcome=indeterminate`、`operational_disposition=current_state_accepted`、`authority=local_user_presence`、`replayed=false` を保持し、解除するのは quarantine だけです。exact old operation ID は permanent tombstone のままで、terminal receipt や completed/not-executed claim は作りません。northbound MCP tool でもありません。Shell/process/filesystem と allowlist 外 capability は fail closed します。
- **Replay tombstone/history separation (#136):** 完了。詳細 retirement audit は64件で rotation し、別の lossless compact exact-ID tombstone index が restart/migration をまたぐ permanent no-replay を維持します。rotation した audit に対応する full retired operation detail も compact します。index は4096件上限で bounded capacity health を公開し、exhaustion 時は quarantine を維持して追加 retirement を拒否します。v5-v10 state は exact migrate し、detail rotation 後の downgrade は拒否します。
- **Recovery & Reconciliation sequencing（2026-09-02 dogfood）:** #103/#137/#136 と #256 / PR #258 は完了済みです。#227 / PR #252 は automated green・physical Windows acceptance pending、#228 / PR #259 は implementation/CI complete・physical Linux acceptance pending です。#253/#254/#115 は完了済みで、#255 Human historical-resolution guidance も完了済みで、bounded recovery dogfood-hardening lane は完了です。released safety/recovery invariant failure の新 evidence が出た場合だけ blocker に昇格します。
- **Installed runtime/operator compatibility (#253):** `v2_doctor` / `v2_status` は recovery 前に exact manifest/runtime pairing、operator tool の stale/unavailable、authoritative checkpoint reader compatibility を分類します。old-tool/new-runtime 混在は skew/stale として fail closed、reader より新しい checkpoint schema は直接 incompatible と表示し、identity 不明も action-required のままです。`v2_status` はこれらを `inspect_upgrade` へ案内し、diagnostic 自体は read-only で recovery state を mutation probe しません。
- **macOS recovery-key readiness (#254):** `v2_doctor` / `v2_status` はincident前にlocal Secure Enclave sealed representation、exact manifest-verified helper、Hub recovery verifierが実際にpairされているかを表示します。probeはhelperのnon-interactive `public` operationだけを使い、LocalAuthentication/signingは起動せず、boundedなready/unprovisioned/missing/mismatch/helper/unknown stateだけを返します。partial/mismatch provisioningはexplicit `provision_recovery`へ案内し、diagnosticがrecovery authorityをcreate/rotate/replaceすることはありません。
- **Hosted Hub support gate (#215):** [`V2_CLOUD_RUN_HUB.ja.md`](V2_CLOUD_RUN_HUB.ja.md) は現時点の Cloud Run support を NO-GO とします。support claim 前に external durable authoritative state、monotonic writer fencing、stale-writer dispatch denial、platform request timeout より前の proactive Agent stream rotation、fail-closed hosted shutdown、Agent/northbound authentication boundary を分離した one-port h2c routing、rollout concurrency acceptance、physical Agent + real Cua evidence を必須とします。
- **Unix process containment 調査 (#96 / #267):** [`V2_UNIX_PROCESS_CONTAINMENT.ja.md`](V2_UNIX_PROCESS_CONTAINMENT.ja.md) でportable調査を完了し、current process-group guaranteeは広げません。trusted macOS probeでdeliberate `setsid()` escapeを再現し、current SDKのfork-lineage trackingではrace-free descendant containerを作れないことを確認しました。stronger Linux cgroup-v2 containmentは#267へ分離し、persistent workはbackground-shell escapeではなく#106のexplicit lifecycleとします。
- **Product Readiness closeout (#213):** 完了。cross-cutting release gate は恒久 [`../PRODUCT_READINESS.ja.md`](../PRODUCT_READINESS.ja.md) checklist が引き継ぎ、これまで散在していた backup/restore operator boundary は [`V2_BACKUP_RESTORE.ja.md`](V2_BACKUP_RESTORE.ja.md) で明文化しました。#104 filesystem-root separation と #111 reproducible performance benchmark は完了済みです。#215 Cloud Run Hub support-gate design は完了済みですが、durable-state/fencing/one-port-ingress implementation と hosted/physical acceptance が未完了のため Cloud Run は unsupported のままです。#96 調査は完了済みで、Linux-specific stronger containment は managed execution 配下の #267 で継続します。
