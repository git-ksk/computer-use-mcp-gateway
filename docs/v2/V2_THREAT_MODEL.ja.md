# V2 脅威モデル

> **注意:** この文書は [V2_THREAT_MODEL.md](V2_THREAT_MODEL.md) の日本語訳です。英語版が正典（canonical）です。

ステータス: **V2-M1 信頼モデルベースライン**。M0 の前提は引き続き基盤であり、M1 のトランスポート／プロセス制御および残存デプロイギャップは以下に反映されています。

この文書は、委任されたデバイス能力制御プレーンのセキュリティ要求および非要求を定義します。機能リストよりも意図的に厳格です：コントロールは、そのコントロールを回避するために必要なキーまたは実行サーフェスを保有するコンポーネントに対して有効とは見なされません。

## セキュリティ目的

V2 は、Hub、Agent、バックエンドが設計通りに動作する場合に、以下のプロパティを提供するべきです：

1. Agent が、Hub が接続を受理する前に、現在登録されたデバイスキーの所持を証明する；
2. Agent が、Hub コマンドを受け入れる前に、ピン留めされた Hub トランスポートアイデンティティを認証する；
3. 認証された northbound クライアントプリンシパルは、明示的に許可されたデバイス／能力ペアに対してのみ grant を受け取ることができる；M1 Agent ネイティブ操作は、クラスのみの権限ではなく、正確な `DeviceCapability` スコープを使用する；
4. 短命な grant を、あるセマンティック能力クラスまたは正確な M1 デバイス能力から別のものへ拡張できない；
5. 古いデバイス世代、古い能力リビジョン、消費済み／取り消し済み／期限切れの grant、未知の署名キーは fail closed する；
6. Hub および Agent のキー更新は、サイレントなキー置換ではなく、連続性証明を要求する；
7. 1 つのデバイスは同時に最大 1 つの操作のみを実行し、Hub のアドミッションおよびデバイスあたりのキューは有界である；
8. キャンセル、切断、またはあいまいな完了は、状態変更操作の自動リプレイを決して引き起こさない；
9. 通常の監査エビデンスに、生のスクリーンショット、コマンド引数、バックエンド結果、クリップボード値、または認証情報は含まれない；
10. バックエンド固有の名前と応答形式は、Agent アダプタ境界で停止する。

## 信頼境界

```text
authenticated MCP client principal
        |
        | northbound authn result + Hub authorization policy
        v
+---------------- Hub ----------------+
| client policy                        |
| grant-signing authority              |
| transport identity                   |
| admission / lease / audit state      |
+--------------------------------------+
        |
        | signed, versioned Hub-Agent messages
        | + production confidentiality required
        v
+--------------- Agent ----------------+
| pinned Hub trust / device identity   |
| grant verifier set                   |
| single-operation execution gate      |
| backend adapter                      |
+--------------------------------------+
        |
        v
computer-use backend (Cua first)
        |
        v
operating system / desktop / user data
```

northbound クライアント認証、Hub トランスポートアイデンティティ、grant 署名権限、Agent デバイスアイデンティティは、それぞれ別個のクレデンシャルです。1 つのクレデンシャルの所持は、他のクレデンシャルの所持を意図的に意味しません。

## アセット

高価値アセットには以下が含まれます：

- デスクトップセッションおよびそれを通じて視認または制御可能なすべてのデータ；
- Agent デバイス秘密鍵；
- Hub トランスポート秘密鍵；
- Hub grant 署名秘密鍵；
- northbound クライアント認証状態および認可マッピング；
- 競合するまたはリプレイされたアクションを防止するために使用される操作／リース状態；
- 能力アドバタイズメントおよび世代／リビジョン状態；
- 監査エビデンスおよび取り消し状態。

生のスクリーンショット、生のバックエンド応答、コマンド引数は、保持するとプライバシー影響が増大するため、意図的に通常の制御プレーン監査アセット**ではありません**。

## コンポーネントごとの脅威

### 悪意のあるまたは侵害された MCP クライアント

クライアントは、別のデバイスを選択したり、より強い能力を要求したり、以前の grant をリプレイしたり、Hub をフラッドしたり、バックエンド固有のパラメータを悪用したりする場合があります。

コントロール：

- Hub は、クライアント提供のデバイスアイデンティティを認可として信頼するのではなく、すでに認証されたプリンシパルアイデンティティを消費する；
- M0 は `principal -> device -> capability class` をサポートし、M1 Agent ネイティブ操作はさらに正確な `principal -> device -> DeviceCapability` 認可をサポートし、クラスのみの grant を Agent 境界で拒否する；
- クライアントは Agent デバイスキーまたは Hub トランスポートキーを受け取らない；
- grant は署名済み、デバイスバウンド、ワンショット、Agent 強制で最大 5 分の有効期限を持つ；M1 Agent ネイティブ grant は正確なデバイス能力にもバウンドされる；
- グローバルアドミッションおよびデバイスあたりのキューは有界である；
- Hub-Agent プロトコルは、任意の Cua ツール名／引数ではなく、型付きセマンティックコマンドを公開する。

M1 northbound 境界は、新しい OAuth サーバーではなく、MCP Authorization protected-resource 側を実装します。`v2_hub` は RFC 9728 メタデータを公開し、ヘッダー Bearer 提示を要求し、設定された RFC 7662 イントロスペクションエンドポイントを通じてトークンを検証し、受け入れられたトークンを設定された MCP リソースオーディエンスにバウンドし、検証されたサブジェクトと設定された認可サーバーイシューアから `AuthenticatedClientPrincipal` を構築します。必須の OAuth スコープが MCP リソースへのエントリーをゲートし、別個のローカル principal -> device -> 正確な `DeviceCapability` ポリシーが委任されたデバイスアクセスに対して権威を持つことを維持します。Bearer ヘッダーは rmcp ハンドラディスパッチ前に削除され、型付き Hub-to-Agent コマンド／grant パスに Bearer フィールドは存在しません。

残存リスク：認可サーバー／イントロスペクションの可用性とクレデンシャル漏洩は引き続きデプロイ信頼依存であり、パブリック HTTPS ターミネーションとレート制限は現在のループバック northbound リスナーの外部に位置します。侵害された Hub は、自分の grant 権限を使用して有効な Agent grant をまだ発行できるため、OAuth は既に文書化されている完全侵害 Hub 信頼失敗を軽減しません。

### 侵害された Hub

完全に侵害された Hub は**重大な信頼失敗**です。Hub は通常、認可、アドミッション、トランスポート署名、grant 発行を制御します。攻撃者がアクティブな Hub トランスポートキーと grant 署名権限の両方を入手した場合、Agent はそれらのコマンドを認証された Hub コマンドと区別できません。

依然として被害範囲を軽減または回復を支援するコントロール：

- トランスポートアイデンティティと grant 署名キーは別個で独立して更新可能；
- Agent 信頼の変更には署名されたキー更新連続性が必要；
- grant はスコープ付きで短命のまま；
- Agent は grant 署名、デバイス世代、能力リビジョン、単一操作実行を独立して検証；
- バックエンド／Agent ポリシー上限は Hub grant よりも厳格である場合がある；
- 最小化された監査エビデンスは、生のデスクトップデータを保存せずに調査を支援できる。

非要求：暗号は、完全に侵害された認証された Hub を無害にすることができません。M1/M3 デプロイメントでは、grant 署名キーを Hub プロセスから分離するか、危険な能力について別の承認権限を要求することを検討すべきです。

### 侵害された Agent

侵害された Agent は、その OS アカウントで利用可能なデスクトップ能力を悪用したり、バックエンド結果を偽ったり、プロトコルの外部でローカルデータを公開したりする可能性があります。

コントロール：

- Hub は、将来のセッションのために登録されたデバイスアイデンティティを取り消すことができる；
- デバイスキーの更新には、古いキーと新しいキーの連続性証明が必要；
- Hub 監査は、結果が登録された Agent アイデンティティによって署名されたことを記録できる；
- 古い／再接続された世代は Hub で fail closed する。

非要求：Hub は、侵害された Agent が正直なデスクトップ状態を報告したこと暗号的に証明したり、プロトコルの外部で実行されたローカルアクションを防止したりすることはできません。Agent ホストは引き続き高信頼マシンであり、最小特権の OS／バックエンドポリシーを使用するべきです。

### 侵害されたバックエンド

悪意のある computer-use バックエンドは、Agent セマンティックアダプタの下で実行され、要求されたセマンティックを無視したり、追加のローカルアクションを実行したり、結果を捏造したりする可能性があります。

コントロール：

- バックエンド固有の動作はアダプタ契約の背後に分離される；
- アダプタ準拠は正規化された能力アドバタイズメントおよび結果型を検証する；
- 能力アドバタイズメントは明示的でバージョン付きである；
- Agent は実用可能な最も狭いバックエンドポリシー／OS 権限を適用すべき。

非要求：アダプタだけでは悪意のあるバックエンドをサンドボックス化できません。バックエンド出所、バージョンピン留め、OS 分離は引き続き必須のデプロイメントコントロールです。

### ネットワーク攻撃者

ネットワーク攻撃者は、ピアを偽装したり、メッセージを変更したり、以前のハンドシェイク／コマンドをリプレイしたり、機密メタデータを観察したり、接続を終了したりする可能性があります。

M0 ですでに証明されているコントロール：

- 新鮮な Agent および Hub ナンスが各認証トランスクリプトをバウンドする；
- Agent はピン留めされた Hub アイデンティティを検証する；
- Hub は登録されたデバイスアイデンティティを検証する；
- セッション受入、コマンド、キャンセル、結果、キャンセル確認は署名済みで接続バウンドである；
- オーバーサイズフレームは宣言されたペイロード割り当て前に拒否される；
- 署名された Hub 時刻が Agent の単調経過時間に grant 期限評価をアンカーする；
- ディスパッチ後の接続損失は耐久性のある `Indeterminate` 状態および正確な操作デスクトップ隔離（quarantine）となり、自動リプレイされることはない；
- 権威ある Hub 操作記録はさらに発行者／サブジェクト所有権およびデバイス世代をバウンドするため、競合するプリンシパルまたは古い Agent 世代は操作を解決できない；
- 再接続／生存確認は隔離をクリアできない；明示的解決は永続化ゲート付きで監査可能である。

P0 実行安全の詳細と残存回復前提は [`V2_P0_EXECUTION_SAFETY.md`](V2_P0_EXECUTION_SAFETY.md) に記録されています。

現在の M1 エビデンスには、ピン留めされた証信書信頼／ドメイン検証による TLS 保護 gRPC 双方向ストリーミングと、独立した Ed25519 アプリケーション認証が含まれます。以前の raw-TLS トランスポートは回帰／参考実装として残っており、専用 ALPN 付き TLS 1.3 のみです。オペレーター向けの単一デバイス `v2_hub` デーモンが存在し、`v2_agent` と同様にエンドツーエンド TLS/gRPC テストでカバーされています。残存デプロイメントリスクは引き続き存在します：パブリックエンドポイントの堅牢化、接続／TLS ハンドシェイクレート制限、実際の northbound 認証、本番証明書ライフサイクルはまだ完了していないため、これはまだ本番エクスポージャー要求ではありません。

### リプレイおよび古い状態の攻撃者

コントロール：

- grant ID は 1 回消費され、取り消される場合がある；
- 未知／廃止された grant 署名キーは fail closed する；
- デバイス世代は再接続およびクレダンシャル更新時に変更される；
- 能力リビジョンはすべてのコマンド／結果で検証される；
- 操作 ID は終端／不確定状態として保持され、サイレントに再利用されない；M1 は非常に長期間の世代における終端 Agent トンブストーンに対して依然として有界なプルーニング／ロールオーバーセマンティクスを必要とする；
- ハンドシェイク証明リプレイは新鮮なナンスに対して失敗する。

完了／キャンセル済みリプレイトンブストーンは認証されたデバイス世代によって有界です。新しい世代は古い署名済みコマンドが実行ゲートに到達する前に古くなるため、古い終端 ID はプルーニングされる場合があります。`Indeterminate` Hub 操作は意図的にこのプルーニングから免除され、明示的なオペレーター解決までデバイスを隔離し続けます。

### サービス拒否

コントロール：

- 有界なワイヤーフレーム；
- 有界な Hub グローバルアクティブ操作；
- 有界なデバイスあたりのキュー；
- 単一のアクティブ Agent 操作；
- 既存の V1 northbound 同時実行制御は概念的に V2 Hub のアドミッション層とは別個のものである。

残存リスク： Those bounds 外のリソース枯渇（接続数、TLS ハンドシェイク、上流アイデンティティプロバイダー、ホスト CPU／メモリ）には、デプロイメントレベルのレート制限と可観測性が必要です。

## キャンセルおよびあいまいな結果

状態変更 computer use は、トランスポート応答が失われただけで安全にリトライできるものではありません。

ルール：

- ディスパッチ前のキャンセルは Agent 実行を防止する；
- ディスパッチ後のキャンセルは署名済み Hub->Agent リクエストおよび署名済み Agent 確認である；
- Agent はリプレイを拒否するために、再起動後にも終端操作 ID を永続化する；保持セットは 1 つの非常に長期間の世代の内部ではまだ有界ではなく、M1 受入項目である；
- ディスパッチ後の Hub 接続損失は操作を `indeterminate` とマークする；
- `indeterminate`、`completed`、`cancelled` 操作 ID は再准入できない；
- `indeterminate` 操作は Hub のアドミッションでそのデバイスを隔離するため、明示的な解決まで別の操作も拒否される；
- 再接続は既存の世代バウンド操作リースを転送しない。

Agent ネイティブプロセスキャンセルは GUI バックエンドキャンセルよりも強力です：Unix プロセスグループおよび Windows Job Objects は監督対象プロセスツリーを終了し、トップレベルプロセスが完了した場合にバックグラウンド子孫もクリーンアップされます。Cua MCP アダプタは代わりに正確な実行中ダウンストリームリクエスト ID にキャンセルを伝播しますが、伝播はデスクトップサイドエフェクトが停止した証明とは見なされません。伝播されたキャンセルまたはタイムアウトは、したがって `indeterminate` disposition およびデバイス隔離にマッピングされます。同じルールは、変更リクエストがディスパッチされ、バックエンドが後で汎用ツールエラー、不正／証明不能な完了、または応答チャネルを失った場合に適用されます：これらの失敗形式は非実行を証明せず、`BackendOutcomeUnproven` として分類されます。読み取り専用コマンドは明確なバックエンドエラーを返すことができます。バックエンドレベルの非実行証明の欠如は、成功したキャンセルまたは安全なリトライと解釈されてはなりません。

## ブラウザ転送データ境界

ブラウザ転送は意図的にファイルシステムアクセスよりも狭いです。アップロード northbound トラフィックは有界なバイトとパスセーフな論理名を運び、コンテキスト／世代／リビジョンバウンドのワンショット ref を生成し、そのバックエンド値は Agent プライベートなステージングハンドルです。Agent は硬化された状態ディレクトリの下に実際のファイルを作成し、シンボリックリンク／ディレクトリ／置換／サイズ違反を拒否し、southbound Cua 呼び出し直前に正規の通常ファイルを再証明します。生のホストパスは northbound 呼び出し元から受け入れられたり返されたりすることは決してありません。

ダウンロードは呼び出し元からデスティネーションパスまたはルート capabilities を受け入れません。Agent はプライベートな操作ごとの正規ルートを作成し、正確な `BrowserDownload` 認可と新鮮なクリック可能なページ ref を Cua の reviewed MCP-host 批准メカニズムにマッピングし、不透明 id が単一コンポーネントでないか、またはオブジェクトが正確なルート内の直接の通常ファイルでない Cua 完了を拒否します。報告された長さ、実際の長さ、呼び出し元の上限、グローバル 16 MiB 上限はすべて一致する必要があります。論理名衝突には明示的な上書きが必要で、置換は新しいオブジェクトが安全に最終化された後にのみ発生します。

転送 refs およびステージングはコンテキスト／世代／リビジョンライフサイクルとともに廃止されます。確定的なディスパッチ前検証／拒否障害は直ちにクリーンアップされます。プロバイダーディスパッチ後のキャンセル、タイムアウト、汎用バックエンドエラー、応答喪失、または証明不能な完了は、ティアダウンまで Agent プライベートなステージングのみを残し、通常の不確定隔離に入ります。これは実行中のバックエンド読み取り／書き込みと競合するのを回避し、no-auto-replay を保持します。したがって、脅威モデルは侵害された Agent/Cua プロセスのサンドボックス化を主張するものではなく、侵害されていない V2 境界が汎用ホストファイルシステム権限を northbound に公開しないことを主張します。

## キー更新

### Agent クレダンシャル更新

論理デバイス ID は安定したままです。置換には、現在登録されたデバイスキーと提案された新しいデバイスキーの両方によって署名された更新ステートメントが必要です。更新は現在の能力セッションを無効にし、再接続前に世代状態を進めます。

現在の Agent キーが連続性証明のために利用可能ではなく喪失した場合、回復は明示的な管理者再登録フローでなければならず、通常のインバンド更新として表されてはなりません。

### Hub トランスポートアイデンティティ更新

Agent はピン留めされた Hub 検証キーで開始します。各インバンド置換には、単調増加更新エポックと古い Hub キーと新しい Hub キーの両方からの署名が必要です。現在の信頼されたキーから連鎖しないキーは拒否されます。

### Grant 署名キー更新

grant トークンは署名キーを識別します。Agent は制限された重複期間中、古い grant 検証器と新しい grant 検証器を一時的に信頼できます。古い検証器の退役は、その名目上の TTL が経過していない場合でも、そのキーからの新しく提示された grant を fail closed させます。

## クロックモデル

grant 発行／期限時間は Hub で発生します。署名されたセッション受入は Hub wall-clock 時刻を運びます。検証後、Agent はそのアンカーをローカル単調時刻で進め、接続中の grant 検証に派生された時間を使用します。

これは、通常の wall-clock ズレまたは後方 wall-clock 調整が grant をサイレントに延長するのを回避します。完全に侵害された Agent は自分の実行環境を偽造できます。これは上記の侵害された Agent の非要求でカバーされています。

## プライバシーおよび監査

通常の監査イベントには、デバイス ID、世代、grant ID、操作 ID、セマンティック能力クラス、ポリシー結果、理由、タイミングメタデータなどの安定した識別子が含まれる場合があります。

生のスクリーンショット、生のバックエンド出力、生のコマンド引数、クリップボード値、入力されたテキスト、認証情報、完全なアクセシビリティツリーを含むべきではありません。意図的にこれらの内容を含むデバッグキャプチャは別個の高感度モードであり、暗黙的に有効にしてはなりません。

## V2-M1 受入および残存デプロイメント責任

V2-M1 実装ゲートは 2026-08-12 にパスしました。M1 コードには、検証された northbound プリンシパル構築、本番キー／証明書ライフサイクル手順、有界なサービス接続／レート制限、有界なリプレイプルーニング、実 Cua キャンセル隔離、OpenTelemetry/OTLP 統合、OS サービスパッケージングが含まれます。 [`V2_M1_ACCEPTANCE.md`](acceptance/V2_M1_ACCEPTANCE.md) を参照してください。

脅威モデルは引き続き、デプロイメントがこれらの外部責任を保持することを要求します：

- パブリック認可サーバー／イントロスペクションエンドポイントおよび Hub の設定されたイシューア／リソース／オーディエンスは、1 つの信頼境界としてレビューされるべき；
- raw TCP/TLS ハンドシェイクフラッドは、ホストファイアウォール／セキュリティグループおよび、使用する場合は reviewed リバースプロキシ／ロードバランサーによって制約されるべき。アプリケーション層の制限は意図的にトランスポートが受入された後に開始される；
- アプリケーションキーの回復材料および systemd/macOS 認証ファイルは、リポジトリの外部で保護されるべき。古い Hub／デバイスキーの損失はサイレントに通常の連続性更新に変換されてはならない；
- `ExecuteProcess` および `Shell` は引き続き正確な `Dangerous` capabilities であり、ファイルシステムサンドボックスではない；cwd/root チェックは任意の process argv または shell 構文を制約しない；
- macOS GUI 自動化は引き続きオペレーター制御の Cua/TCC 信頼境界に依存し、侵害された Agent またはデスクトップバックエンドは上記の非侵害保証の外部に位置する；
- デフォルトテレメトリはペイロードフリーのままである必要がある。コレクタ／プロキシボディログまたは高感度デバッグキャプチャの有効化は、別個の機密データ境界を作成する；
- `indeterminate` 操作は明示的な解決まで隔離されたままである必要がある。ネットワーク回復、バックエンド再接続、またはサービス再起動は、それをリプレイする許可ではない。

これらはデプロイメント前提／残存リスクであり、欠落した V2-M1 プロトコル機能ではありません。マルチマシンアイデンティティ、フリートアテステーション、ネイティブ GUI アダプタは意図的に後のマイルストーンに延期されています。
