Status as of 2026-09-25:

- **Release sequencing:** `v0.8.0 — Backend Portability & Recovery Safety` is the released baseline. Live control/capability/registry/Hub-Agent schemas remain 12/8/8/6; durable execution-safety is v15 and Agent M1 persistence remains v6. The admitted v0.8 scope is #377 authoritative Hub pre-enqueue non-delivery settlement, #379 structured semantic-refusal remediation, #380 explicit constrained execution-environment/PATH semantics, and #222 second-real-backend portability evidence. #139 signed-token dogfood, #217 recovery parity, and #228 physical Linux FIDO2 remain separate withheld support-claim gates; Cloud Run #215 remains unsupported.
- **Desktop semantic path:** complete and accepted, including same-context native element click/type/key targeting and real-Cua background AX element-action evidence.
- **Browser core semantic path:** complete and accepted for prepare, bind, inspect, navigate, click, type, dialog, and pointer semantics.
- **Browser transfer:** complete and accepted. Upload/download use scoped CUMG refs plus Agent-private bounded staging; no arbitrary host path is exposed northbound. Agent startup now preserves privacy while reporting the exact bounded staging-init stage and I/O class locally when private staging cannot be established.
- **Optional first-class Human Handoff:** accepted in CUMG for bounded Window and Terminal/PTY coordination. Window uses upstream `WindowHandoffAdapter`; Terminal uses upstream `TerminalHandoffAdapter` while CUMG retains PTY/process containment and content-free verification. The controlled Agent owns the canonical Handoff runtime/checkpoint and Human surface; the Hub keeps CUMG authorization, ledger, quarantine, and conservative pre-dispatch fencing. Runtime/transport loss fails closed rather than bypassing Handoff. Upstream Window #85 still tracks its own first-class same-LAN direct physical rerun; CUMG #152 remains closed.
- **Current execution-safety boundary:** durable execution-safety schema is **v15**. Ambiguous effectful work remains `Indeterminate`, quarantines the device, and is never automatically retried or replayed. Schema v6 distinguishes text/input delivery that was applied but not committed from true no-effect resolution. Schema v7 adds a payload-free, privacy-preserving text-input evidence envelope with optional keyed candidate matching. Schema v8 adds the closed recovery-evidence read lane: explicitly allowlisted non-mutating evidence reads may run while quarantine exists, while generic shell/process and every mutation/activation/write capability remain blocked. Schema v9 adds caller-retained status-only effectful response-loss recovery. Schema v10 adds a separate local-user-presence `current_state_accepted` retirement disposition for reviewed low-impact ambiguity without changing the historical `Indeterminate` outcome. Schema v11 separates permanent exact replay tombstones from the bounded 64-entry detailed retirement history; the compact tombstone index is independently bounded at 4096 and fails closed on exhaustion. Schema v12 adds privacy-bounded semantic-authorization admission evidence (snapshot revision/digest plus constraint kind/rule ID). Schema v13 adds explicit mutation-resume barriers/records for acknowledged-unknown PointerClick current-state acceptance, requires fresh-generation Human re-arming before new mutations, and rejects downgrade when v13 state would be lost. Schema v14 adds bounded private recovery-target identity for newly admitted application launch/termination ambiguity; historical v13 state remains readable, while target-bearing v14 state cannot be lossily downgraded. Schema v15 adds Hub-authoritative pre-enqueue non-delivery evidence only when command encoding fails before enqueue or the bounded Hub→Agent mpsc rejects the frame without accepting it. The Hub persists the terminal `cancelled` / confirmed-not-executed record before releasing live state; any failure after successful enqueue remains ambiguous and follows the existing `Indeterminate` / quarantine path. v15 evidence never authorizes replay, and a fresh operation ID is required for any later effectful attempt.
- **Operator inspection and reconciliation:** `v2_maint inspect-quarantine` is read-only and reports the exact earlier `blocking_operation_id` plus bounded recovery metadata without raw payloads or owner identity. `v2_maint audit-reconciliation` correlates the latest Hub/Agent durable state and explicitly distinguishes authoritative terminal evidence from legacy/non-authoritative markers and observational correlation. Neither command clears quarantine or authorizes replay. `compare-quarantine-request` remains correlation-only and returns only `same_request`, `different_request`, or `unavailable`.
- **Operator-ready incident brief (#233):** `v2_maint incident-brief` composes the exact #133 reconciliation audit with bounded quarantine metadata and optional closed-schema diagnostic observations. External findings are forced to `observational_only`/`unavailable`, cannot claim authority or widen `supported_decisions`, and contradictions are surfaced without overriding CUMG evidence. The brief can also report the shared mutation owner/epoch read-only as available/unavailable/not-requested. JSON and compact text output are read-only and exclude raw request/result/desktop/log payloads.
- **Authoritative self-reconciliation and retirement:** execution-safety schema v4 persists an exact effectful dispatch fence and can self-resolve only an exact signed Agent terminal proof after a fresh authenticated generation; v5 adds a separate offline retirement path for narrowly allowlisted permanently unknowable legacy ambiguity while keeping the exact operation ID permanently non-replayable. Automatic settlement, manual resolution, and retirement are deliberately distinct states and all remain persistence-gated.
- **Authoritative backend execution receipts (#290):** an effectful backend may opt into a reviewed, payload-free durable receipt contract bound to the exact operation/device generation/capability revision/capability/dispatch grant/provider identity and relevant #289 target. Exact receipts are persisted in Agent M1 state schema **v6**, converted into the existing `AgentTerminalEvidence`, and flow through the existing signed #124 self-reconciliation path; Hub execution-safety is v15 in released v0.8 while live control/capability/Hub-Agent schemas remain unchanged. Historical Agent state schema v5 remains readable without receipts, while receipt-bearing v6 state cannot be lossily downgraded. The default adapter and current Cua MCP adapter provide no reviewed durable receipt lookup, so Cua response loss before a definite Agent result remains `Indeterminate` / operator-required; logs/current-state heuristics remain observational only.
- **Verified single-Mac backup/restore (#347):** the packaged macOS workflow now creates a coherent snapshot only with reviewed writers stopped and the shared mutation-authority lock held; it preserves exact CUMG/Handoff runtime identity, durable Hub/Agent state, reviewed in-root trust/secrets, mutation owner/epoch, quarantine and replay barriers while excluding browser/ephemeral/runtime staging, locks, logs, sockets, caches and stale recovery-key copies. A canonical manifest requires an externally stored SHA-256 for restore. Restore is non-running/staged first and explicit activation second, only to the exact clean profile path; it never manufactures settlement, changes mutation authority, or claims snapshot freshness. Post-activation quarantine can change only through the existing authoritative recovery/reconciliation path such as an exact persisted #290 receipt.
- **Offline recovery compatibility:** authority-bearing `v2_maint resolve` requires the Hub to be stopped and preserves the authoritative checkpoint's existing durable writer contract. The maintenance binary validates representability before publication and must be installed as a version-paired artifact with the deployed Hub. A newer arbitrary maintenance checkout is not a supported way to mutate state owned by an older deployed Hub. Issue #100 is complete: trusted physical-macOS Secure Enclave/user-presence acceptance resolved a real ambiguous desktop operation without replay, and the durable resolution remained authoritative after Hub restart.
- **Constrained process/shell environment contract (#380, v0.8.0):** `execute_process` and `shell` clear the child environment and inherit only an allowlisted subset from the Agent service environment. `PATH` is inherited from that service environment when present, never from login/interactive profile loading; caller `env.PATH` override remains denied, and an executable outside the service `PATH` should be addressed by reviewed absolute path. Tool schemas expose the bounded policy through `x-cumg-execution-environment` without revealing raw PATH/environment values or creating discovery/authorization authority.
- **Structured semantic-refusal remediation (#379, v0.8.0):** existing stable refusal codes remain canonical; known browser/interaction/capability/session refusal classes can additionally return bounded `required_actor`, `next_action`, `same_operation_replay_safe=false`, `remediation_is_authority=false`, and `fresh_call_required` metadata. The mapping is provider-neutral and additive, unknown codes gain no guessed remediation, and hints never authorize implicit foreground switching, browser-route fallback, scope expansion, consent, or replay. `mutation_resume_required` explicitly names the local user as the required actor while `device_indeterminate` keeps its stronger existing reconciliation guidance.

- **Second real-backend portability (#222, v0.8.0):** macos-mcp 0.4.0 implements a narrow `ComputerUseBackendAdapter` slice for `ListApplications`, `MovePointer`, and `PointerClick`. Unknown internal failures still collapse fail closed.
- **Host reliability and diagnostics:** `v2_doctor` distinguishes a proven in-band diagnostic self-observation from real blocking quarantine without changing restart-safety state. Controlled `StorageFull` injection proves Agent checkpoint persistence exhaustion can terminate the Agent fail closed and therefore surface remotely as `agent_offline`; the prior committed checkpoint/replay barriers remain authoritative, normal service-manager reconnect works after capacity returns, and `v2_doctor` exposes only coarse read-only state/temp capacity signals.
