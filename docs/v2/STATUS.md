# V2 status

> English is the canonical documentation. [日本語版 / Japanese translation](STATUS.ja.md)

Status as of 2026-09-02:

- **Desktop semantic path:** complete and accepted, including same-context native element click/type/key targeting and real-Cua background AX element-action evidence.
- **Browser core semantic path:** complete and accepted for prepare, bind, inspect, navigate, click, type, dialog, and pointer semantics.
- **Browser transfer:** complete and accepted. Upload/download use scoped CUMG refs plus Agent-private bounded staging; no arbitrary host path is exposed northbound. Agent startup now preserves privacy while reporting the exact bounded staging-init stage and I/O class locally when private staging cannot be established.
- **Optional first-class Human Handoff:** accepted in CUMG for bounded Window and Terminal/PTY coordination. Window uses upstream `WindowHandoffAdapter`; Terminal uses upstream `TerminalHandoffAdapter` while CUMG retains PTY/process containment and content-free verification. The controlled Agent owns the canonical Handoff runtime/checkpoint and Human surface; the Hub keeps CUMG authorization, ledger, quarantine, and conservative pre-dispatch fencing. Runtime/transport loss fails closed rather than bypassing Handoff. Upstream Window #85 still tracks its own first-class same-LAN direct physical rerun; CUMG #152 remains closed.
- **Current execution-safety boundary:** durable execution-safety schema is **v11**. Ambiguous effectful work remains `Indeterminate`, quarantines the device, and is never automatically retried or replayed. Schema v6 distinguishes text/input delivery that was applied but not committed from true no-effect resolution. Schema v7 adds a payload-free, privacy-preserving text-input evidence envelope with optional keyed candidate matching. Schema v8 adds the closed recovery-evidence read lane: explicitly allowlisted non-mutating evidence reads may run while quarantine exists, while generic shell/process and every mutation/activation/write capability remain blocked. Schema v9 adds caller-retained status-only effectful response-loss recovery. Schema v10 adds a separate local-user-presence `current_state_accepted` retirement disposition for reviewed low-impact ambiguity without changing the historical `Indeterminate` outcome. Schema v11 separates permanent exact replay tombstones from the bounded 64-entry detailed retirement history; the compact tombstone index is independently bounded at 4096 and fails closed on exhaustion.
- **Operator inspection and reconciliation:** `v2_maint inspect-quarantine` is read-only and reports the exact earlier `blocking_operation_id` plus bounded recovery metadata without raw payloads or owner identity. `v2_maint audit-reconciliation` correlates the latest Hub/Agent durable state and explicitly distinguishes authoritative terminal evidence from legacy/non-authoritative markers and observational correlation. Neither command clears quarantine or authorizes replay. `compare-quarantine-request` remains correlation-only and returns only `same_request`, `different_request`, or `unavailable`.
- **Operator-ready incident brief (#233):** `v2_maint incident-brief` composes the exact #133 reconciliation audit with bounded quarantine metadata and optional closed-schema diagnostic observations. External findings are forced to `observational_only`/`unavailable`, cannot claim authority or widen `supported_decisions`, and contradictions are surfaced without overriding CUMG evidence. The brief can also report the shared mutation owner/epoch read-only as available/unavailable/not-requested. JSON and compact text output are read-only and exclude raw request/result/desktop/log payloads.
- **Authoritative self-reconciliation and retirement:** execution-safety schema v4 persists an exact effectful dispatch fence and can self-resolve only an exact signed Agent terminal proof after a fresh authenticated generation; v5 adds a separate offline retirement path for narrowly allowlisted permanently unknowable legacy ambiguity while keeping the exact operation ID permanently non-replayable. Automatic settlement, manual resolution, and retirement are deliberately distinct states and all remain persistence-gated.
- **Offline recovery compatibility:** authority-bearing `v2_maint resolve` requires the Hub to be stopped and preserves the authoritative checkpoint's existing durable writer contract. The maintenance binary validates representability before publication and must be installed as a version-paired artifact with the deployed Hub. A newer arbitrary maintenance checkout is not a supported way to mutate state owned by an older deployed Hub. Issue #100 is complete: trusted physical-macOS Secure Enclave/user-presence acceptance resolved a real ambiguous desktop operation without replay, and the durable resolution remained authoritative after Hub restart.
- **Privacy-safe northbound failures / actionable indeterminate UX (#115):** live control schema is **v9**. Expected execution-policy/runtime failures preserve bounded client-visible categories such as working-directory denial, timeout, program/environment policy, spawn failure, cancellation, `agent_offline`, and `device_indeterminate` while raw paths, commands, environment values, device identity, provider text, and OS error strings remain excluded. `device_indeterminate` additionally states that execution may already have occurred, marks blind replay unsafe, prefers exact `get_operation` + reconciliation, and requires a fresh operation ID for later effectful work; no command-text heuristics or replay authority are introduced. Unknown internal failures still collapse fail closed.
- **Host reliability and diagnostics:** `v2_doctor` distinguishes a proven in-band diagnostic self-observation from real blocking quarantine without changing restart-safety state. Browser staging startup failures emit bounded local stage/I/O diagnostics. Controlled `StorageFull` injection proves Agent checkpoint persistence exhaustion can terminate the Agent fail closed and therefore surface remotely as `agent_offline`; the prior committed checkpoint/replay barriers remain authoritative, normal service-manager reconnect works after capacity returns, and `v2_doctor` exposes only coarse read-only state/temp capacity signals.
- **Effectful response-loss recovery (#103):** every effectful process/shell/Desktop/Browser tool accepts a stable caller-retained `operation_id`, and Hub-local `get_operation` rechecks exact owner plus current exact-capability authorization without Agent liveness or replay. Process/shell retain bounded output; other effectful Desktop/Browser operations persist only a payload-free `effectful_status` marker plus authoritative state/receipt. The bounded recovery archive remains 8 entries / 256 KiB encoded total; unknown/evicted references never make the original operation retry-safe. Schema v9 checkpoints carrying this marker cannot downgrade to v8.
- **Local-user online quarantine recovery:** implemented behind explicit recovery-key provisioning. The Agent device key is not recovery authority; a fresh Hub-signed challenge is resolved only by a separately pinned P-256 endpoint recovery key. The initial macOS signer uses a Secure Enclave key with user-presence access control. Automated protocol/persistence coverage and trusted physical acceptance are complete: authorization was published only after local user presence, the ambiguous operation resolved durably, restart preserved the resolution, and the old operation was not replayed.
- **Lane-scoped operator readiness (#226):** `v2_doctor` now adds a privacy-bounded readiness summary derived from existing authenticated state/capability/quarantine authority. It distinguishes control-plane, Computer Use observation, filesystem observation, generic effectful execution, and browser-effectful execution. Durable quarantine reports effectful lanes as `indeterminate_fenced` without hiding independently healthy observation lanes; missing/mismatched evidence reports `unavailable`/`unknown` rather than green. This summary is diagnostic only and cannot resolve, retry, replay, dispatch, or grant authority.
- **Durable single-Mac maintenance status (#234):** the reviewed source-build upgrade writes an owner-private atomic transaction record with exact CUMG/Handoff source identities, durable phase, bounded terminal class, target runtime generation, rollback identity, mutation-authority owner/epoch, and explicit completion gates. `v2_maint upgrade-status` is read-only and never resumes/retries maintenance or changes quarantine/authority. Source builds default to two Cargo jobs, refuse below a 6144 MiB free-space floor before transaction/service mutation, and classify later Cargo ENOSPC as `build_storage_exhausted` before install.
- **Durable online-recovery confirmation (#109):** the Agent now verifies the exact Hub-signed `RecoveryResolved` acknowledgement against the pending authorization, atomically stores an owner-private receipt before clearing challenge/authorization handoff files, and clears an old receipt when a fresh challenge arrives. `v2_recover resolve --wait-secs` and `v2_recover confirm` report durable completion only after verifying the exact request/device/generation/operation/decision; local authorization publication alone remains explicitly non-terminal.
- **Unified operator status (#235):** `v2_status` is now the normal first single-Mac diagnostic. JSON schema v1 composes existing #226 readiness, quarantine/recovery, Handoff status, mutation authority, verified runtime identity, and #234 maintenance state into bounded `overall`, `primary_reason`, and `next_action` fields without creating a second authority/state machine. The human renderer is derived from the same schema. Handoff locators/IDs, device/principal identity, payloads, credentials, grants, and fingerprints are omitted.
- **Guided quarantine recovery (#236 / #255):** `v2_recover guide` keeps authoritative #233 `supported_decisions` unchanged and separately exposes a Human-only historical-assertion lane when that set is empty. Plan schema v2 marks the Human lane interactive-only and automatic-selection forbidden; Agent/LLM/diagnostics cannot widen the authoritative set. Any Human assertion reuses existing `confirmed_completed` / `confirmed_not_executed` with inconclusive audit assessment, exact challenge/incident revalidation, Secure Enclave user presence, #109 durable acknowledgement, no replay, exact quarantine-clear verification, and the existing #235 `v2_status` post-check. `--json` remains read-only planning only.
- **Artifact-backed Product Readiness path (#237):** the macOS single-Mac release candidate is now source-free for CUMG/Handoff runtime code, binds exact CUMG/Handoff commits in closed manifests, includes local-user recovery tooling, verifies before activation, supports a clean first install with separately provisioned trust/secrets, and reuses the existing one-shot durable upgrade/paired rollback contract. Installed `v2_doctor` and `v2_status` must both be healthy before install success. Linux/Windows remain reviewed candidate evidence rather than official binary-installer claims.
- **Local-Human current-state acceptance (#137):** complete. `v2_recover accept-current-state` is a separate authority-bearing macOS path for reviewed `Scroll`/`MovePointer` ambiguity only. It reuses the separately provisioned Secure Enclave recovery key and fresh signed challenge, requires a strictly newer authenticated/durable generation, persists `execution_outcome=indeterminate` plus `operational_disposition=current_state_accepted` / `authority=local_user_presence` / `replayed=false`, removes only the quarantine, and permanently tombstones the exact old operation ID. It does not create a terminal receipt, does not claim completed/not-executed, and is not exposed as a northbound MCP tool. Shell/process/filesystem and every non-allowlisted capability fail closed.
- **Replay tombstone/history separation (#136):** complete. Detailed retirement audit rotates at 64 records while a separate lossless compact exact-ID tombstone index preserves permanent no-replay across restart/migration; old full retired operation detail is compacted with rotated audit. The index is capped at 4096, exposes bounded capacity health, and refuses further retirement with quarantine intact at exhaustion. v5-v10 state migrates exactly; downgrade after detail rotation is rejected.
- **Recovery & Reconciliation sequencing (2026-09-02 dogfood):** #103/#137/#136 and #256 / PR #258 are complete. The provider-neutral WebAuthn/CTAP verifier is now on `main`. #227 / PR #252 remains automated-green and physical-Windows-acceptance pending; #228 / PR #259 is implementation/CI-complete and physical-Linux-acceptance pending. #253/#254/#115 are complete; #255 Human historical-resolution guidance is implementation-complete in this change, completing the bounded recovery dogfood-hardening lane unless new evidence exposes a released safety/recovery invariant failure.
- **Installed runtime/operator compatibility (#253):** `v2_doctor` and `v2_status` now classify exact manifest/runtime pairing, operator-tool staleness/availability, and authoritative checkpoint-reader compatibility before recovery. Mixed old-tool/new-runtime binaries fail closed as skew/stale, a checkpoint schema newer than the reader is reported directly as incompatible, and unknown identity remains action-required. `v2_status` routes these states to `inspect_upgrade`; the diagnostic is read-only and does not probe by mutating recovery state.
- **macOS recovery-key readiness (#254):** `v2_doctor` / `v2_status` now expose whether the local Secure Enclave sealed representation, exact manifest-verified helper, and Hub recovery verifier are actually paired before an incident. The probe uses only the helper's non-interactive `public` operation, never triggers LocalAuthentication or signing, and reports bounded ready/unprovisioned/missing/mismatch/helper/unknown states. Partial or mismatched provisioning points to explicit `provision_recovery`; diagnostics never create, rotate, or replace recovery authority.
- **Product Readiness closeout (#213):** complete. The standing [`../PRODUCT_READINESS.md`](../PRODUCT_READINESS.md) checklist now carries the cross-cutting release gate; [`V2_BACKUP_RESTORE.md`](V2_BACKUP_RESTORE.md) closes the previously scattered backup/restore operator boundary. #215/#104/#111/bounded #96 remain compatible non-blocking stabilization unless new evidence exposes a released invariant failure.
- **V1 compatibility:** V1 remains available for regression/reference and existing deployments. V1 regression/conformance coverage remains required during V2 work; the remaining #14/#15 observations are explicitly blocked on upstream Cua rather than treated as active CUMG release blockers.
